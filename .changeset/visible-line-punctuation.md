The fold's visible line now always ends in terminal punctuation, and its length cap is explicitly soft. First live consumer round (agent-settings#105) posted both folded comments with the raw headline-style subject as the visible line: no trailing period (the contract never asked for one and `joinProse` only repaired the copy inside the fold), so a long unpunctuated clause sitting directly over the collapsed `context` chip read as a truncated comment.

Renderer: `renderContextFold` and `renderPrLevelFold` (the review body's `Full finding` block puts a bare subject over a collapsed block the same way) normalize the visible line through the new `ensureTerminalPunctuation`, `joinProse` now calls it instead of keeping a second copy of the core-strip rule (closing-quote/bracket/emphasis stripped before the terminator test, period placed after the closers), and `buildJudgePrompt`'s fold branch applies the same normalization so the judge sees the bytes that post. Rendering-only: `claim.subject` is untouched, so dedup's prefix-match semantics never see the added period. Expected output-shape effect: folded visible lines (inline and pr-level) gain at most one trailing `.`, while short comments and fold interiors are byte-identical. `renderPrLevelFold` also gains `renderContextFold`'s block-close guard on the discussion, so a pr-level claim whose discussion quotes a literal closing details tag now posts flat in the review body instead of ending the `Full finding` block early (a longer body in that rare case, the fold's collapse preserved in every other). The prose judge's fold branch calls `renderContextFold` directly and its label-shape units go through `joinProse`, so judge and renderer agree byte for byte on both the visible line and the block's opening. A trailing `:` or `;` stays terminal on purpose, matching joinProse's glue rule: a subject that hands off mid-thought into the block is a contract violation for the judge to bounce, not a shape for the renderer to repair.

Contracts and rubric: the subject/summary field contracts now say the line is the only text visible when the discussion folds, so it carries the defect and the ask (one short sentence by default, two when it takes both, and a question's subject contains the question), replacing the flat-era "one line that stands alone" wording that was sized for a paragraph opener with the discussion visible below it. `LABEL_RUBRIC_EXTRA` replaces the hard "one or two lines" phrasing with the soft cap (overshoot built from padding or restatement violates rule 3, length alone does not) and adds the question rule: a question-labeled comment whose visible line contains no question is a rule 3 violation, since agent-settings#105's `question (non-blocking)` comment buried its actual ask as the last sentence of the fold. The revised rubric lines extend the calibration debt from the fold PR: the live pass on the fixtures (host-side, `eval/judge-prose-live.ts`) must run before the release bump that ships them.
