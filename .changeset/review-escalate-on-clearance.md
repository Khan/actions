A fast re-review that clears the last blocking thread now ends in an approval. Before, a `fast` round whose reconciler resolved every blocking thread could only dismiss the standing request-changes review, because approval requires a full-roster round. The author then waited on a later full round, or commented `/review`, for an approval their fix had already earned. Now the dispatcher runs the reconciler first on a PR with a standing block, drafts included. When every blocking thread is resolved, or no bot thread is left open because a person resolved them all, the same run continues as a full round over the whole diff (plan reason `clearance-escalation`). That full round re-judges the whole diff, so an issue behind a wrongly resolved thread is found again and blocks. That round posts blocking findings only and approves unless the fix introduced a new blocker. Its approval also posts the guidance comment and requests the owning teams, which a once-blocked PR never got before. Canary runs, `flip-gated`, and rounds that keep or lose track of a blocking thread don't escalate. An escalated round that loses its correctness or skill pass falls back to the fast round, which dismisses the block unless the surviving pass found a new blocker. Body size: an escalated round's body grows by the depth note (about 140 characters), plus one collapsed line per validated non-blocking finding that would otherwise have posted inline, and its inline comments drop to blocking findings only. A fallback adds one note line (about 130 characters). Every other run is byte-identical.
