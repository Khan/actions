Skill-doc only: record three operational lessons from the 2026-07 preview trials in the `review-trial` skill. (1) Never force-push a trial branch between rounds: a round that cannot anchor on a prior fingerprint reports `stampSource: null` in `out/rereview-plan.json` and executes `depth: full` with `staging: whole-diff` even where ROUTING says `scoped`, which is indistinguishable from a genuine carrier gap and silently voids that round's scoped-cost sample. `stampSource` in the plan artifact is the authoritative anchoring signal and must be read every round; the carrier internals that make a rebase the wrong suspect (content-hashed hunk signatures, a `commitSha` that is written but never read back) are dated implementation properties, not contracts. (2) Use a fresh lock filename per trial: GitHub's workflow registry keys the display name to the file path and keeps the stale one, so two trials that reused `review-preview.lock.yml` both listed as "PR Reviewer" while the files declared "PR Reviewer Preview v1.8.0" and "...v1.9.0". Concurrency was unaffected, but a run list naming every arm after the production reviewer invites the "did production just run?" scare the naming rule exists to prevent. (3) A lifecycle plan that means to exercise open-thread suppression must leave at least one finding unfixed, since a push where the fixer repairs everything lets the reconciler resolve every thread and `threads.json` comes back empty. No change to the shipped review workflow.
