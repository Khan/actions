# Same-run duplicate findings, September 3–8, 2026

The published webapp reviews reproduce the reported 13 groups across 11 PRs: 28 comments for 13 overlapping concerns, or 15 extra comments, including 9 extra blocking comments. These are author-facing overlap counts, not permission to discard 15 claims. Several groups contain independent obligations that a consolidated comment would still need to state.

The investigation found one deterministic advisory merge bug. In webapp#42034, an earlier model proposal reserves a tier-1 head and then merges nothing because the blocking-member guard fires. A later grounded proposal loses that head, so its advisory member posts separately. The fix reserves heads only after a proposal makes a merge. It leaves the blocker guard, similarity thresholds, cross-file restrictions, validation, and thread suppression unchanged.

## Reproduce

From the repo root, run `pnpm exec vitest run workflows/review/lib/dedup-september-audit.test.ts`. This checks the 12 groups with available original claims, the complete 31-candidate reservation case, independent-claim retention, structural and grounding negatives, attribution, recorded validation, and the request-changes verdict.

Run `node -r @swc-node/register workflows/review/eval/replay-same-run.ts` for machine-readable scores, failed floors, path/source/blocker barriers, recorded proposals, and the full reservation replay. The numeric diagnostics mirror the private text-selection function and are checked against the production predicate in the test.

The baseline is `review-v1.25.0`, commit `8c13cc7bf9dc4a444971300a10e4dbf13d0f6f52`. The investigation started at `a5b6eb0`. The PR was rebased onto `088b1a1`. The baseline and working base have identical `dedup.ts`, `dedup-cluster.ts`, `dedup-text.ts`, `dispatch-contracts.ts`, and `dispatch-roster.ts`. No model calls are needed for these replays. The two new reservation assertions failed against the baseline before the fix: the advisory was absent from the merge record, and the later proposal never reached the grounding check.

## Advisory change and limits

Tier 1 still settles first. Each original claim belongs to at most one structurally verified proposal. Different original members can point to one tier-1 head, so the head can now reach a later proposal when an earlier proposal makes no merge. Productive proposals retain exclusive ownership of their considered heads. Tests prevent a successful model cluster from becoming a bridge into another model cluster.

The full fixture goes from 24 to 23 pre-validation claims. Only completeness-2 is newly absorbed into correctness-reviewer-3. Its subject, source, and line 313 are recorded in also_flagged_by, alongside the existing skill-auditor attribution at line 230. Original survivor prose is unchanged. The recorded validator output leaves the same three blocking claim ids and the same REQUEST_CHANGES verdict. All unrelated surviving claims are compared structurally, not just counted.

The remaining five advisory extras aren't fixed by this patch. Three groups are cross-file (#41975, #41997, #42041), one is a partial-overlap proposal omission (#41989), and one becomes a closer duplicate during validation (#42024).

## Blocker consolidation (deferred)

The nine extra blockers are not nine safe suppressions. Preserving REQUEST_CHANGES alone is insufficient: a merged survivor can be refuted while a distinct member is valid, and input/output compatibility or different failure scenarios can require separate fixes.

A separate offline presentation prototype checked record preservation, but it did not establish that grouped comments would be easier to read. That prototype is parked and isn't included in this patch. Before restarting it, compare separate and grouped comments, decide whether grouping is useful, and agree on per-member reply, resolution, adjudication, and autofix behavior. No live grouping or new blocker suppression is authorized.

The following constraints remain requirements for any future experiment, not next steps for this advisory fix:

- Keep every blocking claim as an independently validated object, with its id, label, source, existing corroborating attribution, occurrence anchors, failure scenario, suggested fix, author-dispute state, and validation result. Don't use a model grouping to drop a validator invocation or change a verdict.
- Let the existing identity proposal suggest a presentation group after validation, but require every retained member to render as an individually attributed section. No synthesized replacement prose, hidden member, confidence averaging, or inherited refutation. Compute the review verdict from the original final claim set.
- Start in shadow mode on these eight blocking groups. Record proposed group membership, all member anchors, verdict equality, and preservation of every ask. Render one comment only when the group is readable without truncation and each independent obligation remains visible. Otherwise keep separate comments. Treat #42039's input/output obligations and #42034's two cold-attempt scenarios as required negative checks against oversimplification.
- Design comment ownership before posting any groups. Thread reconciliation, author replies, resolution, autofix, and the dispatch conformance gate currently reason about the existing claim/comment surface. A grouped comment must retain member ids and per-member outcomes, and a resolved container thread must not silently adjudicate all member concerns. If the existing gate can't represent it, shadow output is the only allowed mode.
- Bound the first decision to these 13 audit groups plus existing bridge, wrong-grounding, same-source, cross-file, and missing-output regression fixtures. Require zero missing independent asks, zero lost attribution records, identical verdicts, and explicit reviewer acceptance of every displayed blocker group. Don't generalize to live suppression from a matching aggregate count.
